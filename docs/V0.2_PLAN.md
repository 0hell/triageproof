# v0.2 — Pilot Ready

## Goal

Make TriageProof easy for a new maintainer to install, observe, evaluate, and remove in one short session. v0.2 is a reliability and adoption release, not a feature-expansion release.

## Release scope

### Onboarding

- [x] Provide equivalent English and Simplified Chinese setup paths.
- [x] Make the read-only GitHub Action the recommended five-minute installation.
- [x] Show where Action summaries appear and explain `advisory` versus `strict`.
- [x] Provide a public-safe pilot feedback form.

### Action reliability

- [x] Treat an empty or `null` issue body as an incomplete report instead of an Action error.
- [x] Reject unsupported Action modes with exit code `64`.
- [x] Cover issue, pull-request, empty-body, mode, oversized-event, and untrusted-output behavior in tests.
- [ ] Record one successful public issue-event run in this repository.

### Release consistency

- [x] Align the v0.1 changelog and roadmap with the public tag.
- [ ] Set the package and CLI version to `0.2.0` only after all release gates pass.
- [ ] Publish `v0.2.0`, move the `v0` Action tag, and add truthful release notes.

## Explicitly out of scope

- Automatic comments, labels, closing, or other GitHub write operations
- OpenAI, Codex, agent packets, or model-generated follow-up questions
- Gitleaks integration or broader secret-detection claims
- Custom scoring, allowlists, configuration files, SARIF, or dashboards
- GitLab, Gitee, additional languages, telemetry, or stored issue content

These ideas remain candidates only after pilot evidence demonstrates a shared need.

## Release gates

- `npm run check` passes on the release commit.
- Advisory mode returns success for `ready`, `needs-info`, and `blocked` reports.
- Strict mode maps those states to exit codes `0`, `1`, and `2`.
- Empty issue bodies produce a controlled `needs-info` report.
- Invalid modes and malformed or oversized events fail safely with exit code `64`.
- No Action summary, output, or error reflects the original issue body or detected secret value.
- A maintainer can copy one workflow and find the first summary within five minutes.
- README, changelog, package version, CLI version, tags, and release notes agree.

## Post-release pilot signals

Pilot results measure usefulness but do not block the `v0.2.0` tag:

- three to five external repositories with maintainer consent and installation;
- at least two real, non-demo issue runs;
- at least one maintainer who keeps or continues evaluating the Action;
- at least one maintainer-approved public feedback reference;
- dated counts for useful, neutral, and incorrect warnings without storing issue bodies.

Fixes discovered during pilots should ship as focused `v0.2.x` releases.
